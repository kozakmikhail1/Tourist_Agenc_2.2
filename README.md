# TouristAgency 2.2

Desktop-приложение на **C++17** и **Qt 6** для учебного управления туристическим агентством: роли администратора и пользователя, каталог туров, бронирования, хранение в текстовых файлах.

---

## Работа с файлами (где в коде)

Вся загрузка и запись данных с диска сосредоточена в классе **`AgencyData`**:

| Действие | Файл и функции |
|----------|----------------|
| Поиск каталога `data/` | `AgencyData::dataDirectory()` — `src/agency/agencydata.cpp` |
| Чтение всех сущностей | `AgencyData::loadFromFiles()` — разбор `accounts.txt`, `tours.txt`, `bookings.txt`, проверка контрольных сумм |
| Запись на диск | `AgencyData::saveToFiles()` — `QSaveFile` / `QTextStream`, UTF-8 |
| Вспомогательно | `readAllLines`, `stripChecksumLine`, `ensureDataDir` — в том же `.cpp` |

Файлы данных (по умолчанию рядом с `.exe` или вверх по дереву от рабочей директории, см. логику `dataDirectory()`):

- **`accounts.txt`** — пользователи и хеши паролей  
- **`tours.txt`** — туры  
- **`bookings.txt`** — бронирования  

В конце каждого файла — строка вида `#checksum_...` с контрольной суммой тела файла (алгоритм описан ниже).

Сохранение также вызывается при закрытии окон (`UserWindow` / `AdminWindow`, `closeEvent`).

## Алгоритмы, реализованные самостоятельно

Ниже — логика, написанная вручную в модуле `agency` (не «чёрный ящик» готовой библиотеки):

1. **Хеширование пароля** — `hashPassword()` в `src/agency/algorithms.cpp` (цепочка операций над строкой `login+password` для получения числового хеша в виде строки).
2. **Линейная фильтрация туров** — `filterTours()` в `src/agency/algorithms.cpp`: обход связного списка туров и отбор по стране (подстрока), диапазону цены и диапазону длительности (`0` у границы — «не задано»).
3. **Быстрая сортировка (QuickSort)** — `quickSortImpl` / `quickSortTours()` в `src/agency/algorithms.cpp` (ручная реализация по цене или числу дней).
4. **Хеш-таблица для логинов** — класс `LoginHashTable` в `src/agency/loginhashtable.cpp`: своя **хеш-функция** строки и **разрешение коллизий цепочками** в фиксированном числе корзин (`kBucketCount`).
5. **Контрольная сумма файлов** — `simpleChecksum()` в `src/agency/agencydata.cpp`: проход по тексту и полиномиальное накопление для строки, по которой сверяется `#checksum_*` при загрузке.

Дополнительно:

- **Многоуровневая сортировка по столбцам таблицы** — `sortToursByColumnOrder()` в `src/agency/algorithms.cpp`: свой **компаратор по полям тура**, порядок задаётся списком столбцов; для упорядочивания используется **`std::stable_sort`** из стандартной библиотеки C++ (алгоритм сортировки стандартный, сравнение столбцов — своё).
- **Логика порядка кликов по заголовкам** (три состояния, Shift для второго ключа) — `src/utils/tourtablesortcontroller.cpp` (организация UI-сортировки, не «структура данных» предметной области).

Валидация полей (логин, пароль, тур, диапазоны в фильтре) — `src/agency/validation.cpp` (правила и разбор строк, без отдельного «классического алгоритма» вроде сортировки).

## Динамические структуры данных: свои и готовые

### Реализованы самостоятельно (учебные структуры)

- **Три односвязных списка** на указателях `next` в структурах `Tour`, `User`, `Booking` (`include/agency/agencytypes.h`). Операции вставки в голову, поиска, удаления узлов, обхода — в **`src/agency/agencydata.cpp`**.
- **Хеш-таблица** **`LoginHashTable`** — массив корзин, в каждой — цепочка узлов с логином; используется для быстрой проверки уникальности логина при регистрации (`include/agency/loginhashtable.h`, `src/agency/loginhashtable.cpp`).

### Взяты из Qt / стандартной библиотеки (вспомогательно)

- **`QVector`**, **`QString`**, **`QStringList`**, **`QMap`**, **`QSet`** и др. — для временных коллекций, интерфейса, сообщений.
- Виджеты Qt (`QTableWidget`, диалоги и т.д.) — отображение и ввод данных, не замена списков туров/пользователей в «ядре».

Итог для пояснительной записки: **основное хранилище предметной области** — **связные списки**; **своя хеш-таблица** — для множества логинов; файлы и контрольные суммы — **свой формат и своя проверка**.

## Основные возможности приложения

### Роль `admin`

- Просмотр и управление пользователями (добавление, правка пароля/флага админа, удаление с защитой последнего администратора).
- Просмотр и управление турами (добавление, изменение, удаление; при удалении тура удаляются связанные бронирования).
- Фильтрация списка туров в панели администратора (страна, ограничения по цене и дням — по полям интерфейса).

### Роль `user`

- Фильтрация туров по стране и **диапазонам** цены и длительности (мин/макс, `0` — без ограничения).
- Сортировка результата **по клику на заголовки столбцов** таблицы (циклы «без сортировки → по возрастанию → по убыванию» для одного столбца; **Shift+клик** — дополнительные ключи сортировки); визуальные метки на заголовках и текст в статусной строке.
- Просмотр расширенных полей тура в таблице (в т.ч. адрес отеля, звёздность, даты проведения — см. формат файла ниже).
- Бронирование тура, просмотр и отмена своих бронирований, профиль (смена пароля/логина, выход, удаление аккаунта).

## Сборка и запуск

### Требования

- Qt6 (Widgets + Core)  
- CMake  
- Компилятор с поддержкой C++17  

### Сборка (Windows / PowerShell)

```powershell
cmake -S . -B build
cmake --build build
```

### Запуск

```powershell
.\build\TouristAgency.exe
```

После **первой** сборки шаблон из репозиторного `data/` копируется в `build/.../data` рядом с `.exe` (скрипт `cmake/copy_initial_data_if_missing.cmake`). Если там **уже есть** `accounts.txt`, каталог **не перезаписывается** — регистрации и правки сохраняются между пересборками. Чтобы снова подставить шаблон из репозитория, удалите папку `data` рядом с исполняемым файлом и пересоберите проект (или скопируйте `data/` вручную).

При выходе из программы дополнительно вызывается сохранение всех файлов (`QCoreApplication::aboutToQuit`), плюс сохранение при закрытии окон и после регистрации.

## Формат файлов данных

### `accounts.txt`

`login;passwordHash;isAdmin`  
(`isAdmin`: `0` или `1`)

### `tours.txt`

**Актуальный формат (9 полей):**

`id;country;price;days;hotel;hotelAddress;hotelStars;dateStart;dateEnd`

- `hotelStars` — целое 1…5  
- `dateStart`, `dateEnd` — даты в формате **yyyy-MM-dd**

**Устаревший формат (5 полей)** при загрузке поддерживается: недостающие поля заполняются значениями по умолчанию (сообщение в лог загрузки). После сохранения приложения туры перезаписываются в **9-полевом** виде.

### `bookings.txt`

`id;userLogin;tourId;cancelled`  
(`cancelled`: `0` — активно, `1` — отменено)

Каждый файл заканчивается строкой `#checksum_accounts` / `#checksum_tours` / `#checksum_bookings` с числом — контрольная сумма **канонического** тела файла (как при сохранении), для старых `tours` из 5 полей строка в контрольной сумме остаётся 5-полевой.

## Ограничения валидации (кратко)

- **Логин:** 3–32 символа, буквы (латиница/кириллица), цифры, `_`, без пробелов и `;`.  
- **Пароль:** 4–128 символов, без `;`.  
- **Тур:** непустые страна, название отеля и адрес отеля; без `;` в этих полях; цена и дни в допустимых диапазонах; звёзды 1–5; даты проведения в формате ISO, дата окончания не раньше начала.  

Подробности — в `include/agency/validation.h` и `src/agency/validation.cpp`.

## Примечания

- При первом запуске без корректного `accounts.txt` может быть создан пользователь по умолчанию (см. сообщения `AgencyData::loadFromFiles()`).  
- Пароли в файле хранятся **только в виде хеша**, не в открытом виде.
